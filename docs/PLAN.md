# Polar 개발 계획

목표는 Windows 11 개인 PC에서 Steam, Epic Games, PC Game Pass 설치 게임을 패드로 찾고 실행하는 것이다. 제품 범위와 최종 인수 조건은 [PRD](PRD.md), 화면·언어·조작 기준은 [목업](../polar-mockup.html)을 따른다.

## 개발 순서

| 단계 | 구현 결과 | 완료를 판단할 증거 |
|---|---|---|
| 1. Steam 탐색과 실행 요청 | Rust 라이브러리와 진단용 명령줄 프로그램. 설치된 게임을 읽고 선택한 App ID를 Steam에 전달한다. | 다중 라이브러리 fixture, 오류 격리, CLI 통합 시험, Windows x64 빌드. 이번 개발 단위다. |
| 2. 콘솔형 홈 | Tauri 창에 실제 Steam 목록을 연결한다. 빈 목록, 패드 포커스, 한국어·영어, 캐시, 즐겨찾기와 실행 기록을 제공한다. | 예시 데이터 없이 홈에서 실행 요청까지 수행하고 재시작 후 선택 언어와 라이브러리를 복원한다. |
| 3. Epic과 PC Game Pass | Epic 설치 기록 및 공식 실행 링크, Windows 등록 앱과 게임 메타데이터 대조, 수동 바로가기 추가를 연결한다. | 원본 런처 목록과 대조하고, 부분 실패·삭제·재설치·같은 제목의 다른 플랫폼을 식별한다. |
| 4. Windows 통합 | 실행 상태와 복귀, 실제 전체 화면·자동 시작·바탕 화면 전환, 개인용 설치 파일·업데이트를 완성한다. | 실제 PC에서 플랫폼별 게임 실행·종료, 로그인 개입, 포커스 복귀 및 설정 보존을 검증한다. |
| 5. v1.0 인수 | 패드, 1080p·4K, 300개 항목, 오프라인, 설치·업데이트·제거를 시험한다. | PRD 인수표에 실제 게임명, 기기, 측정값, 자동 또는 수동 복귀 결과를 기록한다. |

각 개발 단위는 **설계 → 독립 적대리뷰 GO → 실패하는 테스트 작성 → 구현 → 검증 → 별도의 독립 적대리뷰 GO → 로컬 커밋** 순으로 진행한다. NO-GO 사유를 수정한 뒤 같은 게이트에서 재심한다. 구현을 수정하면 검증도 다시 실행한다. 개발 단위의 GO와 실기기 인수 완료는 따로 기록한다.

## 1단계 설계

- **진입점.** `polar list`로 현재 사용자 Steam 설치를 탐색한다. Windows에서는 HKCU의 Valve SteamPath, 없으면 HKLM의 Steam InstallPath(32비트 레지스트리 뷰)를 사용한다. `polar --steam-root <경로> list`는 임의 설치 위치와 OS 독립 fixture 시험에 같은 경로를 제공한다. `polar launch <AppID>`는 운영체제에 등록된 Steam 루트를 매번 새로 탐색한다. 루트 지정은 list 전용이며 launch와 함께 쓰면 레지스트리 조회나 실행 호출 전에 사용 오류로 거부한다. CLI는 개발 진단용이며, 제품 UI는 같은 Rust 함수를 호출한다.
- **탐색.** 기본 루트의 steamapps와 libraryfolders.vdf의 숫자 항목을 읽는다. 기존 VDF 파서를 사용하고 구형 문자열 경로와 신형 객체의 path를 모두 처리한다. 공백·한글·이스케이프된 Windows 경로를 보존한다. 기본 라이브러리가 설정 파일에서 빠져도 읽는다.
- **실행 가능한 후보.** appmanifest_<숫자>.acf의 AppState에서 파일명과 일치하는 0 초과 u32 App ID, 비어 있지 않은 이름, 설치 완료 플래그(StateFlags 비트 4), 단일 폴더명 installdir와 steamapps/common 아래 설치 폴더 존재 여부를 확인한다. Steam이 기록한 로컬 앱 후보를 제공하며 게임·도구의 상점 분류는 후속 UI 통합에서 다룬다. ID로 중복을 제거하고 이름·ID로 정렬한다.
- **부분 실패.** 라이브러리나 설치 기록을 읽을 수 없으면 진단에 경로와 원인을 남기고 다른 결과를 반환한다. 손상된 VDF에서도 기본 루트를 탐색한다. CLI는 완전한 목록에 0, 부분 결과에 2, 사용법·전면 실패에 1을 반환한다. 설정 파일 누락은 다중 라이브러리 존재 여부를 알 수 없으므로 진단한다. 적어도 한 steamapps를 열어 일부 결과를 얻으면 진단 유무로 0/2를 구분하고, 어떤 steamapps도 열지 못하면 1이다. 설정 파일과 정상적으로 읽은 빈 라이브러리는 성공이다. launch는 부분 결과에도 선택 ID를 확실히 발견했으면 호출하고 성공 시 0을 반환한다. ID 미발견 또는 실행 요청 실패는 1이다. 이 단계는 설치 기록과 사용자 설정을 쓰지 않는다.
- **실행 경계.** CLI 입력은 숫자 ID만 허용한다. 선택 ID가 실제 탐색 결과에 있을 때만 Rust가 고정 형식 steam://run/<ID>를 만들고 Windows ShellExecuteW의 open으로 전달한다. 사용자 제공 실행문·exe·추가 인자는 받지 않는다. 반환값으로 요청 전달 여부만 보고한다. 비 Windows에서는 탐색 fixture 시험을 지원하고 실 실행 요청에는 오류를 반환한다.
- **검증.** 테스트에서 임시 디렉터리에 VDF·ACF와 설치 폴더를 만들어 정상·부분 실패·중복·누락·거짓 ID·미완료·부적합한 경로·다중 드라이브를 확인한다. CLI 프로세스의 출력과 종료 코드, 실제 OS 호출 직전 생성한 URI를 확인한다. 임의 루트와 launch 조합을 거부하는 CLI 테스트를 포함한다. 테스트가 실제 게임을 실행하지 않도록 fixture 단위에서 경계를 검사한다. fmt, clippy, test, Windows x64 컴파일·링크를 실행한다. 실제 Steam 호출 및 게임 종료는 Windows 실기기 시험 기록을 남길 때 판정한다.

### 1단계 실행 방법

Rust 개발 환경에서는 `cargo test --locked`로 회귀 시험을 실행한다. Windows x64에서 `cargo build --release --locked`로 진단 프로그램을 빌드한다. PowerShell에서 해당 실행 파일이 있는 폴더로 이동한 뒤 다음처럼 사용한다.

```powershell
.\polar.exe list
.\polar.exe --steam-root 'D:\Steam' list
```

목록의 첫 열이 App ID다. 예를 들어 실제 목록에 620이 있는 경우 `.\polar.exe launch 620`으로 실행 요청을 보낸다. 진단 소프트웨어는 Steam 설정이나 게임 파일을 수정하지 않는다.

## 데스크톱 통합 설계 (2–5단계 개발 단위)

Windows 11 실기기가 없으므로 공급 가능한 결과는 설치 가능한 x64 후보와 재현 가능한 자동 시험이다. 게임별 실기기 결과를 가정하지 않는다. 기존 CLI와 목업은 유지하고 단계 2–4의 의존 기능을 한 데스크톱 변경 단위에서 통합한다.

- **앱.** 별도의 Tauri 2 Windows 패키지가 기존 Rust 라이브러리를 공유한다. 내장 HTML/CSS/JS만 로드하고 원격 페이지 및 임의 셸 호출은 허용하지 않는다. UI가 보내는 실행 인자는 플랫폼별 안정 ID 하나다. 셸이 받는 대상은 네이티브 계층이 검증한 대상에서만 만든다. 데스크톱 명령과 CLI의 fixture 루트 경로는 분리한다.
- **탐색.** 세 소스를 독립적으로 비동기 조회한다. Steam은 기존 탐색기와 로컬 표지 캐시를 이용한다. Epic은 ProgramData의 .item과 실제 설치 폴더를 검증하고 식별자를 URL 인코딩한다. Xbox는 현재 사용자 등록 앱 ID와 설치 패키지의 MicrosoftGame.config(또는 검증된 게임 등록 정보)를 대조한다. 비게임 앱은 자동 포함하지 않는다. 일반 앱/파트너 런처 게임은 사용자가 등록 앱 또는 게임 바로가기를 명시적으로 선택해 추가·편집·삭제할 수 있다.
- **캐시와 상태.** 먼저 사용자별 저장 목록을 표시한다. 완전 탐색만 삭제를 확정한다. 부분 실패는 새 결과를 합치고 미확인 항목에는 상태를 표시한다. 즐겨찾기와 최근 실행은 안정 ID로 저장한다. 수동 대상은 사용자 승인된 원본만 Rust에서 보존하며 임시 파일 교체와 직렬화로 실패·동시 갱신을 처리한다. 중복 실행 방지, 다른 소스 오류 격리, 단일 앱 인스턴스, 제목·플랫폼별 식별을 확인한다.
- **실행과 복귀.** 시작 시 현재 소스에서 다시 검증한다. 실행 중복 잠금은 성공·실패·시간초과에서 풀린다. 실행 요청 성공, 게임 감지, 종료, 상태 불명은 구분한다. 로컬 설치 경로에 속한 새 게임 프로세스 또는 창의 수명을 추적해 종료 시 UI 선택을 복원한다. 검증할 수 없는 바로가기·별도 실행기는 수동 복귀를 제공한다. 사용자가 다른 앱을 쓰는 중에 Polar가 입력을 빼앗지 않는다.
- **언어와 UX.** 승인된 홈·라이브러리·설정 구성을 제품 데이터에 연결한다. 표지 없는 게임은 읽기 쉬운 타일을 제공한다. 설정은 창/전체 화면, HKCU 자동 시작, 최소화/종료를 실제로 수행한다. 두 언어의 오류·빈 상태·접근성 레이블·수량·입력 안내, 키보드·표준 게임패드 내비게이션을 시험한다.
- **설치.** 관리자 권한이 필요 없는 사용자별 Windows x64 설치 파일, 시작 메뉴와 제거 진입점을 제공한다. WebView2 확인과 설치 복구 경로를 제공한다. 업데이트는 기존 앱 데이터와 게임을 보존하고 제거는 명시적인 Polar 설치 파일·등록 항목만 삭제한다.
- **게이트.** 설계 GO 뒤 소스 fixture·병합·언어·홈/설정·실행 상태 테스트의 실패부터 확인한다. Rust와 브라우저 시험, Windows x64 release 링크와 설치 파일 검사 후 별도 독립 리뷰를 받는다. 설치·업데이트·제거, 패드와 제3자 게임에서의 실측은 실제 Windows 11에서만 승인한다.

## 데스크톱 통합 진행 기록

- 독립 설계 리뷰 GO. 자동/수동 중복, 설정·제거의 소유권, 300개 목록 탐색 중 입력 유지를 추가 검증 항목으로 선정했다.
- RED 단계에서 Rust catalog 모듈과 JS 모델이 없어 fixture 시험이 실패했다. 수동 저장·세션 경계는 별도 실패 테스트를 추가한 후 구현했다.
- Linux 호스트 Rust 회귀, Windows x64 전체 타깃 clippy, 두 언어 UI 모델, Chromium 통합·입력 회귀를 실행했다. 브라우저의 네이티브 호출 및 게임패드는 시험용 응답이다. 300개 캐시의 10회 표시와 1080p 입력 반응을 측정했다. Windows 부팅·WebView2 초기화 시간은 이 측정에 들어가지 않는다.
- GNU Windows x64 release GUI와 WebView2Loader.dll을 NSIS로 패키징했다. 설치 파일에서 실제 파일을 다시 추출하여 바이트 단위로 대조하고 제거 프로그램을 확인했다.
- Windows 실기기가 없어 세 런처의 실제 로그인/실행/복귀와 설치·업데이트·제거 인수는 미판정이다. 배포 등급은 RC로 둔다.

- 첫 독립 구현 리뷰 NO-GO. 원본 .lnk 선택, 준비 프로그램에서 게임으로 넘어갈 때의 조기 종료, 구형 Epic 바로가기 중복을 수정했다. 추적 상태와 유일한/모호한 Epic 대상에 대한 RED → GREEN 회귀를 추가했다. Steam 로컬 앱 종류와 Xbox 드라이브 설치 위치 대조도 추가 검증했다.
- 독립 구현 재심 **GO**. 같은 리뷰어가 바로가기 원본 선택 플래그, 겹치거나 교체되는 게임 프로세스 추적, 구형 Epic 대상의 유일성 조건을 재검토하고 Rust 15건과 JS 모델 3건을 독립 재실행했다. 설치 파일 추출 대조를 확인한 뒤 Windows x64 RC 커밋을 승인했다.
- 최종 자동 시험에서 Chromium 1080p 입력부터 두 번째 렌더 프레임까지 95백분위 32.5ms, 300개 캐시 목록의 브라우저 초기 표시 10회 7–39ms. 모의 패드의 이동/선택/복귀/분리, 4K 뷰포트의 레이아웃, 오류·수동 등록·삭제·언어 복원을 확인했다. 실제 TV, Windows 네이티브 초기 구동, 물리 패드 지연과 별도로 해석한다.

## RC2 게임 배경

- Steam 게임은 App ID로 Steam 상점에 게시된 실제 스크린샷 원본을 찾는다. Epic·Xbox·수동 게임은 설정에서 제목으로 상점을 검색해 사용자가 같은 게임과 에디션을 한 번 연결한다. Steam에 없는 게임도 SteamGridDB의 고해상도 Hero 원본 이미지 주소를 연결할 수 있다. API 키와 플랫폼 로그인은 요구하지 않는다.
- 홈에는 선택한 게임의 배경 전용 로컬 이미지나 다운로드한 가로 이미지를 사용한다. 최소 1920×1080, 화면 크기는 Windows 배율을 반영한다. 4K 원본을 우선하고 HD만 있으면 원본 픽셀 크기까지 표시한다. 타일 표지와 로고를 확대하지 않는다. 원본이 없을 때는 Polar 기본 배경을 유지한다.
- 온라인 연결은 설정에서 끌 수 있다. 이미 받은 사진은 오프라인에서 읽는다. 게임을 빠르게 넘길 때 입력을 막거나 이전 게임 사진이 뒤늦게 표시되면 안 된다. 다운로드 시간·바이트·이미지 픽셀·동시 작업·디스크 캐시를 제한하고, 저장은 원자적으로 처리한다. 메타데이터와 이미지의 호스트·경로를 제한하고 리디렉션은 따르지 않는다.
- 기존 설정과 목록을 보존한다. Rust 공급자 테스트와 실제 UI의 FHD/4K·오프라인·게임 변경·설정 테스트를 먼저 작성하고 Windows x64 설치 파일을 재검증한다.

### RC2 검증 기록

독립 설계 리뷰 **GO** 후 원본 필터·오프라인 캐시와 화면 표시 테스트의 실패를 확인하고 구현했다. 독립 구현 리뷰에서 최신 Steam 업로드의 해시 하위 경로와 한국어 상점 검색이 누락된 것을 발견했다. 각각 실패 테스트를 추가하고 수정한 뒤 독립 재심 **GO**를 받았다.

- 실제 공급자 호출에서 Forza Horizon 5의 3840×2160 원본 다운로드 및 오프라인 재읽기, ARC Raiders의 해시 경로, ‘데이브 더 다이버’ 한국어 검색을 확인했다. 실제 SteamGridDB 1920×620 Hero는 최소 높이 기준에 따라 제외됐다.
- 호스트 및 Windows 타깃 검사와 Chromium 회귀, Windows x64 릴리스 빌드, 설치 파일에서 추출한 앱·WebView2Loader 바이트 대조가 통과했다. 4K 화면 캡처에는 실제 Polar 프런트엔드와 Forza Horizon 5의 상점 이미지를 사용했다. Windows 11 설치 및 TV 실기기 인수는 남아 있다.

## RC3 고해상도 화면 가독성

홈·라이브러리·설정의 글자와 조작 영역을 1920×1080 논리 화면 기준으로 함께 키운다. 사용 가능한 CSS 너비와 높이 중 작은 비율을 사용하고 1배 아래로 축소하지 않는다. 그래야 4K 전체 화면에서도 글자가 1080p와 비슷한 화면 비율을 차지하고, 높은 Windows 배율이나 작은 창에서는 시스템이 정한 크기를 존중한다. TV에서 읽기 어려운 작은 조작 안내와 설정 레이블도 넓은 화면에서 키운다. 배경 레이어는 실제 출력 픽셀을 기준으로 계속 표시한다.

인수 기준은 한국어·영어 홈, 라이브러리와 설정 대화상자의 실제 글자·버튼 크기와 잘림 여부다. 1080p와 4K(표시 배율 100%, 150%, 200%), 좁은 창 및 리사이즈에서 확인한다. 선택 타일 강조와 키보드 입력, 원본 배경 해상도, 기존 설치 업데이트 경로도 회귀 검증한다.

독립 설계 리뷰 GO 후 기존 4K 100%에서 탭 글줄 실측값 27px가 1080p와 같아 테스트가 실패하는 것을 확인했다. 수정 후 한국어·영어 홈, 라이브러리, 설정 모달과 배경 레이어를 검증했다. 4K 100%·150%·200%에서 전경 글자와 버튼이 1080p 대비 약 두 배의 출력 픽셀을 차지한다. 640×420에서 긴 제목을 선택해도 플레이 버튼과 하단 안내가 보이고 대화상자를 닫으면 키보드 포커스가 돌아왔다. Windows x64 빌드와 설치 파일 추출 대조를 마쳤고 독립 구현 리뷰는 GO다. TV 실기기 및 시청 거리별 확인은 남아 있다.

## RC4 앱 아이콘

Polar의 P를 접힌 오로라 리본 형태로 그린다. 작은 크기에서도 P의 안쪽 공간과 기울어진 줄기가 구분되도록 하고, 투명한 모서리와 어두운 바탕으로 밝거나 어두운 작업 표시줄에서 윤곽을 유지한다. 홈 로고와 Windows ICO는 같은 벡터 원본을 사용한다. 홈의 POLAR 텍스트는 그대로 읽을 수 있게 한다.

16·32·48·64·128·256px 아이콘을 확인하고 Windows 앱, NSIS 설치 프로그램, 제거 프로그램의 기본 아이콘 그룹을 원본과 대조한다. 시작 메뉴 바로가기와 설치된 앱 목록은 기존 Polar.exe 경로를 사용한다. RC3 설치 파일에서 NSIS 기본 아이콘이 확인되었으므로 Modern UI가 읽는 설정도 수정한다.

독립 설계 리뷰 GO 후 RC3의 설치 기본 아이콘 그룹과 홈 마크 테스트가 실패하는 것을 확인했다. 수정 후 같은 SVG로 다시 생성한 ICO는 바이트 단위로 일치했다. 밝고 어두운 바탕의 16px에서 P의 줄기와 안쪽 공간을 확인했다. Windows 앱·설치·제거 파일의 기본 그룹에 든 6개 프레임이 모두 일치했고, 독립 구현 재검토 GO를 받았다. Windows 탐색기·고정 작업 표시줄의 업데이트 직후 캐시 표시는 실기기 인수 항목이다.
