# Polar 제품 요구사항 문서

**Windows 11 개인용 통합 게임 런처 · v1.0 설계 초안**

사용자가 기억해야 할 것은 **하고 싶은 게임의 이름**뿐이다. Polar를 열면 내 PC에 설치된 Steam, PC Game Pass, Epic Games 게임이 한 화면에 보인다. 패드로 표지를 고르고 실행한 뒤, 플레이를 마치면 같은 자리에서 다음 게임을 고를 수 있다.

## 1. 사용자와 완성 기준

주 사용자는 세 플랫폼을 이미 이용 중인 Windows 11 게이밍 PC 소유자다. 책상에서는 키보드와 마우스를, 소파에서는 패드를 사용한다. 기존 게임을 다시 설치하거나 Polar 계정을 만들 필요 없이 시작할 수 있어야 한다.

| 항목 | v1.0 기준 |
|---|---|
| 설치 | 사용자가 Windows 11 x64 PC에서 설치 파일을 직접 실행한다. 개발 도구나 터미널 조작 없이 첫 화면에 도달한다. |
| 평소 사용 | 이미 설치되어 있고 로그인과 업데이트가 끝난 게임은 Polar에서 한 번 선택해 실행한다. 탐색, 실행, 복귀, 앱 종료를 패드만으로 마칠 수 있다. |
| 플랫폼의 역할 | 구매, 게임 설치·업데이트, 구독 자격 확인, 로그인과 클라우드 저장은 기존 플랫폼이 담당한다. 추가 조작이 필요하면 해당 창으로 이동할 수 있다. |
| 배포 범위 | 개인 PC 직접 설치와 새 설치 파일을 통한 업데이트까지 지원한다. Microsoft Store 등록·심사, 공개 배포 서비스는 범위 밖이다. |

제품명 Polar는 작업 폴더에서 가져온 가칭이다. 아래 수치와 지원 기기 범위는 출시 판정을 위한 제안값이다.

## 2. 첫 설치부터 게임 종료까지

1. **처음 열기.** Polar가 설치된 플랫폼과 게임을 찾는다. 한 플랫폼의 탐색이 늦어도 먼저 찾은 게임부터 표시한다. 게임이 하나도 없으면 ‘다시 찾기’와 ‘게임 추가’를 보여준다.
2. **게임 고르기.** 홈 상단에는 최근 실행한 게임 표지가 가로로 놓인다. 처음에는 설치된 게임을 이름순으로 보여준다. 방향키로 타일을 옮기면 선택 테두리와 제목은 즉시 바뀌고, 배경은 뒤따라 전환된다.
3. **실행하기.** 선택한 타일에서 확인 버튼을 한 번 누르면 실행 요청을 보낸다. 연타해도 한 번만 전달한다. ‘실행 요청 중’에는 어떤 플랫폼이 게임을 여는지 표시한다.
4. **돌아오기.** 게임이 실행되는 동안에는 Polar가 화면이나 패드 입력을 가로채지 않는다. 게임 종료를 확인하면 원래 화면의 같은 타일에 포커스를 복원한다. 종료를 판별하기 어려운 게임도 작업 전환으로 Polar를 선택하면 같은 자리에서 곧바로 패드를 쓸 수 있다.

## 3. 화면과 조작

| 화면 | 사용자가 할 수 있는 일 |
|---|---|
| 홈 | 최근 게임을 탐색하고 선택한 게임 아래의 ‘플레이’로 바로 실행한다. 선택한 게임의 제목, 플랫폼, 배경을 한눈에 본다. 전체 라이브러리와 설정으로 이동한다. |
| 라이브러리 | 전체 게임을 이름순으로 보고 플랫폼과 즐겨찾기로 필터링한다. ‘즐겨찾기 → 목록 편집’에서 게임을 선택·해제한 뒤 편집을 마친다. 같은 제목을 두 곳에 설치했다면 플랫폼 표시로 구분한다. |
| 게임 추가 | 자동으로 찾지 못한 게임은 등록된 Windows 앱이나 기존 게임 바로가기를 선택해 추가한다. 이름과 플랫폼을 확인하고 저장한다. 수동 항목을 제거하면 Polar 목록에서만 사라진다. |
| 설정 | 홈 상단의 ‘설정’에서 세 영역으로 이동한다. ‘화면·언어’에서는 언어·전체 화면·움직임 줄이기를, ‘라이브러리’에서는 플랫폼별 탐색 결과·오류와 재탐색을 다룬다. ‘시작·종료’에서는 로그인 시 자동 시작을 설정하거나 ‘바탕 화면으로’와 ‘Polar 종료’를 선택한다. |

**게임 배경.** 게임별 가로 원본(최소 1920×1080)을 사용한다. Steam은 App ID로 상점 스크린샷을 연결하고, 다른 플랫폼은 사용자가 해당 에디션이나 SteamGridDB Hero 원본을 연결할 수 있다. 4K 화면에서는 원본 픽셀 수를 넘어 확대하지 않는다. 받은 사진은 오프라인에서 재사용한다.

**플레이스테이션에서 차용할 경험**은 멀리서 읽히는 제목, 가로로 이어지는 게임 표지, 현재 선택에 따라 달라지는 배경, 예측 가능한 패드 이동이다. 그래픽과 아이콘은 Polar 고유 디자인을 사용한다. 표지나 배경이 없는 게임도 제목으로 식별하고 같은 방식으로 실행할 수 있어야 한다.

- **방향 패드·왼쪽 스틱**으로 이동하고, **확인**으로 실행·선택하며, **뒤로**로 이전 위치에 복귀한다. 버튼 안내는 화면 하단에 둔다. 메뉴를 닫거나 패드를 다시 연결해도 선택 위치를 유지한다.
- **키보드**는 방향키·Enter·Esc로 같은 경로를 지원한다. 마우스로 클릭한 항목과 패드로 조작하는 항목이 일치해야 한다. 텍스트 입력은 일상적인 탐색·실행의 필수 절차에서 제외한다.
- **가독성**은 1080p를 기준으로 확보한다. 4K 전체 화면에서 메뉴·타일·버튼의 비율이 유지되는지 표시 배율 100%·150%·200%에서 확인한다. 밝은 배경에서도 제목과 포커스 테두리를 식별할 수 있어야 한다. 움직임 줄이기를 켜면 배경 확대·이동 효과를 끈다.

### 언어와 지역화(i18n)

- 한국어와 영어를 기본 제공한다. 첫 실행 때 시스템의 선호 언어 순서에서 처음 지원하는 언어를 적용하고, 일치하는 언어가 없으면 한국어로 표시한다. 목업에서는 브라우저의 선호 언어를 사용한다.
- 설정의 언어 선택지는 각 언어 이름인 ‘한국어’와 ‘English’로 표시한다. 언어를 바꾸면 현재 화면, 선택한 게임, 라이브러리 필터를 유지하면서 즉시 전환하고, 다음 실행에도 선택을 기억한다.
- 메뉴·게임 설명·빈 목록·오류·접근성 레이블·키보드 및 패드 안내를 번역 리소스에서 읽는다. 수량과 시각, 플랫폼 이름이 들어가는 문장은 언어별 형식과 어순을 따른다. 공식 게임명과 플랫폼명은 원래 표기를 유지한다.

## 4. 플랫폼별 게임 탐색과 실행

Rust가 로컬 설치 정보를 읽고, 선택한 게임의 실행 요청을 Windows 또는 해당 플랫폼에 전달한다. 프로토콜 지원과 설치 감지 정확도는 별도로 검증한다.

| 플랫폼 | 기본 동작 | 예외 처리 |
|---|---|---|
| Steam | 설정된 각 라이브러리의 설치 기록에서 게임 이름과 App ID를 읽고 Steam 실행 링크로 연다. | 다른 드라이브도 탐색한다. 연결이 끊긴 드라이브의 게임은 일시적으로 사용할 수 없다고 표시한다. [Steam 실행 링크](https://partner.steamgames.com/doc/api/ISteamApps#GetLaunchQueryParam) |
| Epic Games | 로컬 설치 기록을 읽고 Epic Games Launcher의 게임 실행 링크를 호출한다. 가능한 경우 원래 런처 창 표시를 최소화한다. | 로그인·업데이트 등으로 Epic이 창을 열면 사용자가 그대로 진행할 수 있게 한다. [Epic 설치 기록](https://dev.epicgames.com/documentation/en-us/unreal-engine/multiple-launcher-unreal-engine-installs) · [Epic 실행 프로토콜](https://dev.epicgames.com/docs/epic-games-store/protocol-activation) |
| PC Game Pass | 설치된 게임 정보와 Windows에 등록된 앱 실행 항목을 대조해 식별한 게임을 표시한다. 등록 앱은 Windows 실행 경로로 연다. | 시작 메뉴에는 일반 앱도 있고 일부 게임은 빠질 수 있다. 게임 여부가 불분명하면 자동 추가를 보류한다. 별도 실행기가 필요한 타이틀은 동작하는 바로가기를 직접 등록할 수 있게 한다. [Microsoft 앱 식별 문서](https://learn.microsoft.com/en-us/windows/configuration/store/find-aumid) |

새로 고침은 각 플랫폼의 성공·실패를 따로 기록한다. 탐색 실패로 기존 게임과 즐겨찾기가 지워지면 안 된다. 삭제가 확인된 게임은 설치 목록에서 빠지고, 같은 플랫폼의 같은 게임을 다시 설치하면 즐겨찾기가 복원된다. 수동으로 추가한 항목과 자동 감지 결과의 실행 대상이 같으면 한 타일만 표시한다.

## 5. 실패해도 다시 사용할 수 있는 조건

| 상황 | 사용자에게 보이는 결과 |
|---|---|
| 로그인 만료, 구독 확인, 업데이트 대기 | 확인이 필요한 플랫폼 창으로 이동할 수 있다. Polar가 알 수 있는 범위에서 상태를 설명한다. 실행 요청 전달만으로 ‘플레이 중’이라고 표시하지 않는다. |
| 실행 요청 실패, 손상된 바로가기 | 해당 게임 이름과 가능한 조치인 ‘다시 시도’, ‘바로가기 변경’, ‘플랫폼 열기’ 중 적합한 항목을 표시한다. 다른 게임은 계속 선택할 수 있다. |
| 실행 요청은 성공했으나 게임 창을 확인할 수 없음 | ‘실행 상태를 확인할 수 없음’과 ‘홈으로’를 제공한다. 게임이나 원래 런처를 강제 종료하지 않는다. Steam·Epic 클라이언트가 계속 떠 있다는 이유로 게임이 실행 중이라고 판단하지 않는다. |
| 인터넷 연결 끊김 | 저장된 라이브러리, 즐겨찾기, 설정을 열 수 있다. 개별 게임의 오프라인 실행 가능 여부는 원래 플랫폼과 게임의 조건을 따른다. |
| 일부 플랫폼 미설치 또는 읽기 실패 | 해당 플랫폼과 원인을 표시하고 나머지 라이브러리는 정상 동작한다. 재탐색 시 동일 타일이 늘어나지 않는다. |

## 6. 구현 및 데이터 요구사항

- **앱 구조.** Rust가 플랫폼 탐색, 실행, 로컬 저장을 담당한다. UI는 Tauri 전체 화면 창과 HTML/CSS를 기본안으로 한다. UI는 게임 식별자를 넘기고 Rust가 등록된 실행 대상을 확인한다. [Tauri의 Windows 실행 환경](https://v2.tauri.app/start/prerequisites/)
- **로컬 데이터.** 사용자별로 게임 식별자, 플랫폼, 실행 대상, 즐겨찾기, 최근 실행 순서와 설정을 저장한다. 원래 런처의 설치 기록은 읽기 전용으로 취급한다. 계정 비밀번호와 플랫폼 인증 토큰은 수집하지 않는다.
- **설치와 업데이트.** 설치 프로그램이 필요한 실행 환경을 확인하고 부족하면 설치를 안내한다. 사용자가 로그인 시 자동 시작을 선택할 수 있다. 새 버전 설치 중 실패해도 기존 라이브러리와 설정이 보존돼야 한다. Polar 제거 시 게임 파일과 세이브는 그대로 유지한다.
- **성능.** 기준 PC에서 게임 항목 300개를 저장한 상태로 앱을 열었을 때, 10회 중 9회 이상 3초 안에 저장된 목록을 패드로 조작할 수 있어야 한다. 백그라운드 재탐색 중 방향 입력에서 선택 표시까지 걸리는 시간의 95백분위 목표는 100ms 이하다. 기준 PC 사양과 측정 조건을 결과에 함께 기록한다.

## 7. v1.0 인수 시험

아래 항목은 Windows 11 실기기에서 판정한다. 첫 지원 기준은 Xbox 호환 패드 1대와 키보드·마우스다. 실제 사용하는 패드 모델과 연결 방식은 시험 전에 명시한다.

| 시험 | 합격 기준 |
|---|---|
| 처음 설치 | Windows 11 일반 사용자 환경에서 직접 설치 파일로 앱을 열고, 기존 게임 재설치 없이 홈에 도달한다. 플랫폼이 하나도 없는 경우에도 빈 화면에서 게임 추가로 진행할 수 있다. |
| 게임 탐색 | 플랫폼별로 기존 런처에서 정상 실행되는 게임을 최소 2개씩 정해 설치 목록과 대조한다. 기본 지원 경로의 게임은 자동으로 발견하고 일반 앱은 섞이지 않는다. 다른 드라이브의 라이브러리와 수동 등록 경로도 각각 검증한다. |
| 소파에서 한 세션 | 로그인·업데이트가 끝난 대표 게임을 플랫폼별 1개씩 패드만으로 실행한다. 실제 게임 화면을 확인하고 정상 종료했을 때 원래 타일로 돌아와 다음 게임을 실행할 수 있다. 추적이 불가능한 타이틀은 별도로 기록해 수동 복귀 경로를 검증한다. |
| 상태 변화와 복구 | 게임 설치·삭제·재설치, 탐색 실패 후 재시도, 패드 분리·재연결을 수행한다. 타일 중복, 즐겨찾기 소실, 입력 불능이 없어야 한다. |
